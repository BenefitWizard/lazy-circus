## Review Findings

### Critical (3 issues, all fixed)

1. **Negative `agentMaxIterations` caused infinite loop** — `Int` allowed negative values; `go` would never reach `0` from below. **Fix**: Changed to `Natural`.

2. **Tool execution exceptions crashed the agent loop** — `liftIO $ exec toolName argsValue` had no error handling; exceptions propagated out. **Fix**: Wrapped in `tryAny`, feed errors back as tool result JSON so the model can retry.

3. **Crashing `ToolCallExec` placeholder in `newDefaultApp`** — Stub throws `fail` at runtime if called before lens override. **Decision**: Kept as-is (library pattern; documented). The error message is descriptive.

### High (5 issues, all addressed)

4. **Partial `head` in TH `mkSchemaClause`** — Could crash at compile time on empty list. **Fix**: Replaced with pattern matching + `fail`.

5. **Hardcoded model name duplicated** — `"deepseek-v4-flash"` in two places. **Fix**: Extracted `defaultModel` constant.

6. **`response_format` inconsistency** — `askAI` sets `JSON_Object` but `solveWithAgentLoop` doesn't (correct for tool-call rounds). **Fix**: Added explanatory Haddock comment.

7. **ToolDescription/ToolCallExec mismatch risk** — No compile-time guarantee they correspond. **Fix**: Documented as known limitation in `Script.hs`.

8. **String comparison for `finish_reason`** — Compared against raw `"tool_calls"`. **Fix**: Extracted `finishReasonToolCalls` constant.

### Medium (3 issues, deferred)

9. `AIRequest`/`AgentRequest` export constructors — smart constructors would enforce invariants. Deferred (breaking API change).
10. Test performer doesn't capture agent requests for inspection. Deferred (would need existential wrapper).
11. Vector `<>` append in tight loop — O(n) per round. Acceptable for typical agent loops (< 20 rounds).

### Low (3 issues, deferred)

12. Excessive blank lines in `Scene/AI.hs`.
13. Commented-out code in multiple files.
14. `AIScriptDef` positional arguments (consistent with existing pattern).

## Architecture Assessment

The implementation correctly follows Lazy Circus's four-layer architecture:

1. **Scene Language** (`AILangF`): `SolveWithAgent` constructor extends the free-monad DSL with `FromJSON` constraint and continuation, matching the `Ask` pattern.
2. **Performer Class** (`AILangPerformer`): `solveWithAgent'` with default `Nothing` enables gradual adoption — old performers continue working.
3. **Production Performer**: Wires to `solveWithAgentLoop` which reads all dependencies from the reader environment via `Has*` classes.
4. **Test Performer**: Uses default (returns `Nothing`), no API calls in tests.

The TH-generated `mkToolCallExec` creates a closed-over dispatch closure that captures the service lib, `executeToolCall`, and `encodeToolResponse` — all generated by `makeServiceLib`.
