В монорепо появился подпакет lazy-circus-testing: Gherkin-фичи на своём словаре приложения превращаются в исполняемые hspec-сценарии над моками телеграм-исполнителя. Каждый шаг сматчен реестром до прогона — расхождение «спека ↔ код» ловится мета-тестом, а не ревью.

7 новых Bdd-модулей 3 модуля переехали без переименований 92 теста, 0 падений 0 обращений к PostgreSQL hspec — вне рантайма ядра

Что построено

Один пакет — теперь два. Ядро освобождено от тестовых зависимостей, потребители пинят оба пакета из одного git-коммита (subdirs: [., testing] — проверено спайком на stack 3.3.1).

Было

lazy-circus + Testing.* внутри
  • hspec и хелперы жили в рантайм-библиотеке
  • каждый потребитель тянул тестовые зав-сти ядра
  • словарь шагов запекался под одного бота
→

Стало

lazy-circus + lazy-circus-testing
  • ядро — рантайм, ни одного тестового dep
  • testing — hspec как библиотечная зав-сть только здесь
  • resumeace: один пин, две записи subdirs
Нюанс сборки: корневой тест-сьют компилирует testing/src напрямую (source-dirs), потому что пакетная зависимость lazy-circus:test → lazy-circus-testing → lazy-circus — цикл, который отвергают и stack, и cabal. Источники остаются собственностью подпакета.
Bdd.Gherkin

Чистый парсер подмножества Gherkin: AST с номерами строк, And/But наследуют ключевое слово, Outline+Examples раскрываются при парсинге.

Матчерт шаблонов: параметры в "..." и «...», нормализация пробелов, matchAll для пробы неоднозначности.

Как исполняется сценарий

Порядок — это данные: шаги исполняются в порядке документа, потребление журнала двигает курсор только через матч. Ниже — путь от текста фичи до вердикта.

Парсинг и мета-тест — до всякого прогона

parseFeature строит AST с номерами строк и раскрывает Outline по строкам Examples. Мета-тест требует, чтобы каждый шаг каждой фичи сматчился реестром по разрешённому ключевому слову; иначе — один красный тест со списком «фича / сценарий / строка / текст».

несматченный шаг = ошибка сборки спеки, а не зависший прогон

Given — материализация контекста

Действия Given копят контекст: canned-загрузки файлов, очередь AI-ответов, сиды приложения. Контекст по умолчанию пуст — фикстура обязана быть декларирована в спеке явно.

When — пилот через мок-исполнителя

Диалоговые шаги исполняются в TelegramTestScript: sendMessage и иные эффекты уходят в мок-исполнителя, который в той же STM-транзакции публикует сообщение в mailbox и пишет наблюдение в журнал — порядок двух механизмов стабилен по построению.

Mail и AI журналятся через хуки приложения — словарь ваш

Then — курсорное ожидание

awaitObservation сканирует журнал, пропуская потреблённое; первый матч потребляется, недождавшее — AwaitTimeout с явной ошибкой. Селективный шаг, пропустивший чужое наблюдение, не прячет его от следующих шагов (обобщение deferred-buffer).

And-продолжение и снапшот

«Сообщение содержит …» читает последний потреблённый ответ без ожидания и без движения курсора. После сценария раннер отдаёт приложению полный снапшот журнала — негативные проверки («больше ничего не отправлено») делаются по нему.

Анатомия feature-файла

Реальный пример из echo-smoke: три сценария, And-продолжение и видимый @blocked-скип. Справа — что именно читает парсер.

эхо-бот.feature — инлайн в EchoSmokeSpec.hs
Feature: Echo bot dialog

  Scenario: echoes the words of the user
    Given the echo bot is awake
    When the user sends "hello, echo"
    Then the bot replies with "hello, echo"

  Scenario: reuses the reply in an And-continuation
    Given the echo bot is awake
    When the user sends "the road is long"
    Then the bot replies with "the road is long"
    And the bot replies with a message containing "road"

  @blocked
  Scenario: sings a lullaby (not implemented yet)
    Given the echo bot is awake
    When the user sends "lullaby"
    Then the bot replies with "lullaby"

Словарь шагов из коробки

Библиотека даёт готовые Then-конструкторы и Given-комбинаторы. Словарь приложенческий: свои шаги регистрируются рядом, и «первый зарегистрированный матч выигрывает» — порядок регистрации часть контракта.

Then

the bot replies with "$text"

Точный ответ. Ждёт сообщение бота и потребляет его; текст сверяется дословно.

Then · And-продолжение

the bot replies with a message containing "$frag"

Фрагмент последнего ответа. Читает уже потреблённое сообщение — без ожидания и без движения курсора.

Then

the bot replies with a keyboard

Клавиатура. Наблюдение несёт markup ответа; потребление наполняет dsLastKeyboard.

Then

the bot reacts to a message

Реакция. Ждёт ObsTgReaction по целевому сообщению.

Then

the bot deletes a message

Удаление. Ждёт ObsTgDelete.

Then

the bot sends a document

Документ. Ждёт ObsTgDocument; fileId фиксируется в журнале.

Given

stagedTgDownloads

Canned-загрузки. Регистрирует файлы, которые бот сможет «скачать» в сценарии.

Given

queuedAiAnswers

Очередь AI-ответов. Canned-ответы потребляются AI-моком FIFO.

Given

withAppSeed

Слот сидов приложения. DB-фикстуры — забота приложения; комбинатор даёт им место в контексте. Контекст по умолчанию пуст.

Реестр и раннер: точка сборки

Фича + реестр + бутстрап приложения = вызов gherkinSpec. Реестр собирается на сценарий — параметры из его шагов доступны при сборке (так echo-реестр достаёт "$msg" из When-шага).

минимальный боевой каркас (по мотивам EchoSmokeSpec.hs)
-- фича из файла или инлайном
spec :: Spec
spec =
  gherkinSpec
    (FeatureInline "эхо.feature" echoFeature)
    -- реестр на сценарий: параметры шагов уже видны
    (\scenario -> pure (echoRegistryFor scenario))
    -- бутстрап: приложение без БД, журнал через tcJournal
    (\journal -> pure (echoExecutor journal))
    -- вердикт после сценария: снапшот журнала в ваших руках
    echoVerifier

echoRegistryFor :: GherkinScenario -> ScenarioRegistry NoServiceLib () TelegramTestScript
echoRegistryFor scenario = mkRegistry $
  [ givenDef "the echo bot is awake" (pure . id)
  , whenDef  "the user sends \"$msg\"" $ \st -> do
      _ <- sendMessage msg          -- пилот уходит в мок-исполнителя
      pure (st, Nothing)
  ]
  <> maybe [] (pure . botReplyContains) containsFrag
  <> [botRepliesWithMessage msg]   -- точный ответ из When-шага
Дерево отчёта: describe на фичу → it на сценарий (строка Outline — свой it с подставленным именем), впереди — мета-тест покрытия и проба неоднозначности реестра. Ограничение: атрибуция упавшего шага — на уровне сценария (Either приходит после прогона пилота); точный шаг виден в тексте StepError.
